Детекция объектов

Классификатор отвечает на вопрос «что изображено». Детектор отвечает сразу на два: какие объекты есть на изображении и где именно каждый из них находится.

Постановка задачи

Детектор возвращает список объектов. Для каждого указываются класс, уверенность (число от 0 до 1) и ограничивающая рамка (bounding box) — прямоугольник со сторонами, параллельными осям изображения. Число объектов заранее неизвестно, и это главное отличие от классификации [2, гл. 6].

Рамку можно записать по-разному, и путаница форматов — частый источник ошибок:

ФорматЗаписьГде используется
Углы(xmin, ymin, xmax, ymax) в пикселяхPascal VOC, torchvision
Угол и размер(xmin, ymin, w, h) в пикселяхCOCO
Центр и размер(xc, yc, w, h), нормированные на размер изображенияYOLO

Пересечение по объединению

Чтобы понять, насколько предсказанная рамка совпадает с истинной, используют меру IoU (Intersection over Union), или индекс Жаккара [7; 33]:

IoU(A, B) = площадь(A ∩ B) / площадь(A ∪ B) = |A ∩ B| / (|A| + |B| − |A ∩ B|)

IoU равен 1 при полном совпадении и 0, если рамки не пересекаются. Обычно предсказание считается верным при IoU ≥ 0,5.

Подавление немаксимумов

Детектор, как правило, выдаёт несколько сильно перекрывающихся рамок для одного объекта. Алгоритм NMS (non-maximum suppression) оставляет из них одну:

  1. отсортировать рамки класса по убыванию уверенности;
  2. взять рамку с наибольшей уверенностью и добавить её в результат;
  3. удалить все оставшиеся рамки, у которых IoU с ней больше порога (обычно 0,45–0,7);
  4. повторять шаги 2–3, пока рамки не закончатся.
from torchvision.ops import nms
keep = nms(boxes, scores, iou_threshold=0.5)   # индексы оставленных рамок

Метрика mAP

Предсказания одного класса сортируют по уверенности. Каждое считается истинно положительным, если его IoU с ещё не сопоставленной истинной рамкой не меньше порога, иначе — ложноположительным. Двигаясь по списку, строят кривую «точность — полнота» (precision–recall). Площадь под ней — AP (average precision) для класса, а среднее по классам — mAP [32; 33].

  • mAP@0,5 — при пороге IoU 0,5, стандарт Pascal VOC (20 классов);
  • mAP@[0,5:0,95] — среднее по десяти порогам от 0,5 до 0,95 с шагом 0,05, стандарт COCO (80 классов). Требует точной локализации.

Классические детекторы

Скользящее окно. Окно фиксированного размера проходит по изображению на нескольких масштабах, и для каждой позиции классификатор решает, есть ли там объект. Подход прост, но требует десятков тысяч вызовов классификатора.

Метод Виолы — Джонса (2001) [27] впервые позволил находить лица в реальном времени. Он использует простые признаки Хаара, которые быстро вычисляются по интегральному изображению, отбирает лучшие признаки алгоритмом AdaBoost и выстраивает классификаторы в каскад: большинство окон отбрасывается на первых, самых дешёвых ступенях.

HOG + SVM (2005) [28] описывает окно гистограммами направлений градиента в небольших ячейках и классифицирует его линейным SVM. Метод стал стандартом для обнаружения пешеходов до эпохи нейросетей.

Двухстадийные детекторы

Двухстадийные детекторы сначала предлагают области, где может быть объект, а затем классифицируют каждую и уточняют её рамку.

  • R-CNN (2014) [34]: около 2000 областей-кандидатов алгоритмом selective search, каждая отдельно прогоняется через CNN. Точно, но очень медленно.
  • Fast R-CNN (2015): изображение проходит через CNN один раз, признаки областей вырезаются из общей карты признаков слоем RoI Pooling.
  • Faster R-CNN (2015) [15]: области-кандидаты предлагает сама сеть — Region Proposal Network. В каждой точке карты признаков она оценивает набор якорей (anchors) — шаблонных рамок нескольких размеров и пропорций — и предсказывает, есть ли в якоре объект и как сместить его границы.

Одностадийные детекторы

Одностадийные детекторы предсказывают классы и рамки за один проход сети, без отдельного этапа предложений. Они быстрее и подходят для работы с видео в реальном времени.

  • YOLO (You Only Look Once, 2016) [16] делит изображение на сетку S × S. Каждая ячейка предсказывает несколько рамок с уверенностью и вероятности классов. В первой версии при S = 7, двух рамках на ячейку и 20 классах выход сети — тензор 7 × 7 × 30. Модель работала со скоростью около 45 кадров в секунду. Современные версии семейства развивает компания Ultralytics [21].
  • SSD (2016) предсказывает объекты на картах признаков нескольких масштабов: крупные карты отвечают за мелкие объекты, мелкие — за крупные.
  • RetinaNet (2017) [24] решает проблему дисбаланса: фоновых якорей в тысячи раз больше, чем якорей с объектами. Функция потерь focal loss FL = −(1 − pt)γ · log pt уменьшает вклад лёгких, уверенно классифицированных примеров.
  • Безъякорные детекторы (FCOS, CenterNet) предсказывают центр объекта и расстояния до его границ без шаблонных рамок.
  • DETR (2020) [25] формулирует детекцию как предсказание множества объектов трансформером. Предсказания сопоставляются с разметкой венгерским алгоритмом, поэтому NMS не нужен.
from ultralytics import YOLO

model = YOLO("yolo11n.pt")             # маленькая модель, предобучена на COCO
result = model("street.jpg")[0]
for box in result.boxes:
    print(result.names[int(box.cls)], float(box.conf), box.xyxy.tolist())
result.save("street_detected.jpg")

Двухстадийные детекторы исторически точнее, одностадийные — быстрее. Современные одностадийные модели почти сравнялись с двухстадийными по точности, поэтому в прикладных задачах чаще всего начинают с YOLO.

Упражнения для самостоятельной работы

Упражнение 5.1. IoU и NMS вручную

Детектор выдал три рамки класса «собака» в формате (xmin, ymin, xmax, ymax): A = (10, 10, 50, 50) с уверенностью 0,9; B = (12, 14, 52, 54) с уверенностью 0,8; C = (60, 60, 100, 100) с уверенностью 0,7. Выполните NMS с порогом IoU = 0,5.

Упражнение 5.2. Своя функция NMS

Реализуйте NMS на NumPy и сравните результат с torchvision.ops.nms на 1000 случайных рамках.

Упражнение 5.3. Анализ ошибок детектора

Запустите предобученную модель YOLO на 20 собственных фотографиях. Выпишите пропущенные объекты и ложные срабатывания и сгруппируйте ошибки по причинам: малый размер, перекрытие, необычный ракурс, плохое освещение.

Упражнение 5.4. Конвертация разметки

Напишите функцию, переводящую рамку из формата Pascal VOC в формат YOLO. Проверьте её на рамке (100, 50, 300, 250) для изображения 640 × 480.

Пример выполнения упражнения 5.1

Площадь каждой рамки: 40 · 40 = 1600.

IoU(A, B). Пересечение по x: от max(10, 12) = 12 до min(50, 52) = 50, ширина 38. По y: от 14 до 50, высота 36. Площадь пересечения 38 · 36 = 1368.

IoU(A, B) = 1368 / (1600 + 1600 − 1368) = 1368 / 1832 ≈ 0,747

IoU(A, C). По x: от 60 до 50 — отрезок пуст, рамки не пересекаются, IoU = 0.

NMS.

  1. Порядок по уверенности: A (0,9), B (0,8), C (0,7).
  2. Берём A в результат.
  3. IoU(A, B) = 0,747 > 0,5 — B удаляется как дубликат. IoU(A, C) = 0 — C остаётся.
  4. Берём C в результат. Рамок больше нет.

Ответ: остаются рамки A и C — две собаки.

import torch
from torchvision.ops import box_iou, nms
boxes = torch.tensor([[10, 10, 50, 50], [12, 14, 52, 54], [60, 60, 100, 100]], dtype=torch.float)
scores = torch.tensor([0.9, 0.8, 0.7])
print(box_iou(boxes[:1], boxes))          # tensor([[1.0000, 0.7467, 0.0000]])
print(nms(boxes, scores, 0.5))            # tensor([0, 2])
